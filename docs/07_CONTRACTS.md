# قراردادهای سیستمی — مشاور و مراجعه‌کننده

## هدف
بارگذاری و مدیریت **نمونه قرارداد** و قراردادهای امضاشده بین مشاور و مودی به‌صورت سیستمی.

## انواع
1. **قالب نمونه (Template)** — توسط ادمین/حقوقی بارگذاری می‌شود
2. **قرارداد پرونده (Instance)** — پر شده برای یک مشاوره خاص
3. **پیوست امضا** — فایل امضاشده یا تأیید دیجیتال

## مسیر مخزن
```
templates/contracts/
  advisor_engagement.sample.md
  client_consent.sample.md
```

## جریان پیشنهادی
1. ادمین قالب را در `templates/contracts` یا از پنل آپلود می‌کند
2. هنگام پذیرش درخواست مشاوره، سیستم Instance می‌سازد
3. طرفین مشاهده/تأیید می‌کنند (فاز بعد: امضای الکترونیک)
4. فایل در storage خصوصی با دسترسی محدود ذخیره می‌شود

## الزامات حقوقی
- نگهداری نسخه و تاریخ
- عدم افشای قرارداد بین مشاوران
- disclaimer: پلتفرم واسط است نه طرف قرارداد حرفه‌ای مگر خلاف آن تصریح شود

## به‌روزرسانی
- **انسان:** متن حقوقی قالب‌ها، تأیید نهایی
- **AI:** پر کردن فیلدهای غیرحساس از پروفایل؛ **هرگز** امضای خودکار به‌جای انسان
